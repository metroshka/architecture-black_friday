# Шардирование MongoDB

## Цель этапа

Развернуть локальный шардированный кластер MongoDB, настроить маршрутизацию запросов через `mongos`, распределить тестовые данные между двумя шардами и проверить доступ к кластеру через FastAPI-приложение.

## Архитектура

В состав решения входят пять контейнеров:

- `configSrv` — config server, хранит метаданные и конфигурацию шардированного кластера; работает как одноузловой replica set `configReplSet`;
- `shard1` — первый шард, одноузловой replica set `shard1ReplSet`;
- `shard2` — второй шард, одноузловой replica set `shard2ReplSet`;
- `mongos` — маршрутизатор MongoDB, принимает запросы и направляет их на нужный шард;
- `pymongo-api` — FastAPI-приложение, подключённое к MongoDB через `mongos`.

Поток запроса:

```text
Клиент -> pymongo-api -> mongos -> shard1 / shard2
                              |
                              -> configSrv
```

`configSrv`, `shard1`, `shard2` и `mongos` доступны только внутри Docker-сети проекта. На хост опубликован только HTTP-порт приложения.

## Структура каталога

```text
mongo-sharding/
├── api_app/
│   ├── Dockerfile
│   ├── app.py
│   └── requirements.txt
├── scripts/
│   └── mongo-init.sh

```

- `compose.yaml` описывает MongoDB-кластер и API-приложение;
- `scripts/mongo-init.sh` запускает и полностью настраивает кластер;
- `api_app/` содержит исходный код FastAPI-приложения.

## Порты

| Компонент | Порт внутри Docker-сети | Порт на хосте |
|---|---:|---:|
| `configSrv` | `27019` | не опубликован |
| `shard1` | `27018` | не опубликован |
| `shard2` | `27018` | не опубликован |
| `mongos` | `27017` | не опубликован |
| `pymongo-api` | `8080` | `8080` |

## Параметры шардирования

- база данных: `somedb`;
- коллекция: `helloDoc`;
- namespace: `somedb.helloDoc`;
- ключ шардирования: поле `age`;
- стратегия: hashed sharding — `{ age: "hashed" }`;
- тестовые данные: 1000 документов с полями `age` и `name`.

Hashed-ключ равномерно распределяет значения `age` по чанкам и шардам. Такой вариант подходит для демонстрации горизонтального распределения данных, но не оптимален для диапазонных запросов по возрасту.

## Требования

Для запуска нужны:

- Docker с поддержкой Docker Compose;
- Bash;
- свободный порт `8080`;
- доступ к registry `dh-mirror.gitverse.ru` для загрузки образа MongoDB и к registry с образом `kazhem/pymongo_api:1.0.0`.

Команды ниже выполняются из каталога `mongo-sharding`:

```bash
cd mongo-sharding
```

## Запуск

Сделайте скрипт исполняемым, если это ещё не сделано:

```bash
chmod +x ./scripts/mongo-init.sh
```

Запустите автоматическую инициализацию:

```bash
./scripts/mongo-init.sh
```

Скрипт последовательно:

1. запускает config server и оба шарда;
2. инициализирует replica set для каждого узла;
3. запускает `mongos`;
4. регистрирует оба шарда в кластере;
5. включает шардирование базы `somedb` и коллекции `helloDoc`;
6. очищает коллекцию и добавляет 1000 тестовых документов;
7. запускает FastAPI-приложение;
8. выводит состояние кластера, число документов, распределение по шардам и список контейнеров.

Скрипт можно запускать повторно: уже выполненные шаги инициализации будут пропущены, а тестовые данные будут созданы заново.

## Проверка

### Состояние контейнеров

```bash
docker compose ps
```

В списке должны быть запущены контейнеры `configSrv`, `shard1`, `shard2`, `mongos` и `pymongo-api`. Для приложения также должно отображаться сопоставление порта `0.0.0.0:8080->8080/tcp` или эквивалентное ему.

### Проверка API

```bash
curl http://localhost:8080
```

Ожидаемые признаки успешного ответа:

- HTTP-запрос завершается без ошибки;
- `status` имеет значение `OK`;
- `mongo_topology_type` имеет значение `Sharded`;
- `mongo_is_mongos` имеет значение `true`;
- в `collections` присутствует `helloDoc` с `documents_count: 1000`;
- в `shards` присутствуют `shard1ReplSet` и `shard2ReplSet`.

Количество документов можно проверить отдельным запросом:

```bash
curl http://localhost:8080/helloDoc/count
```

Ожидаемое значение `items_count` — `1000`.

### Swagger UI

Интерактивная документация API доступна по адресу:

<http://localhost:8080/docs>

### Распределение данных между шардами

Откройте MongoDB Shell через контейнер `mongos`:

```bash
docker compose exec mongos mongosh --port 27017
```

Выполните в `mongosh`:

```javascript
use somedb
db.helloDoc.getShardDistribution()
```

В выводе должны присутствовать оба шарда — `shard1ReplSet` и `shard2ReplSet` — и количество документов, размещённых на каждом из них. Суммарное количество документов должно быть равно `1000`.

Для выхода из `mongosh` выполните:

```javascript
exit
```

## Остановка и полный сброс

Остановить контейнеры без удаления данных:

```bash
docker compose down
```

Полностью удалить контейнеры, сеть и тома с данными MongoDB:

```bash
docker compose down -v --remove-orphans
```

После полного сброса кластер можно создать заново:

```bash
./scripts/mongo-init.sh
```

## Apple Silicon

На компьютерах с Apple Silicon (`arm64`) Docker может запускать образ `kazhem/pymongo_api:1.0.0` через эмуляцию архитектуры `amd64`. Предупреждение о несовпадении платформ допустимо, если контейнер `pymongo-api` запускается и API отвечает на `http://localhost:8080`.

Если контейнер приложения не стартует из-за несовместимости архитектур, перед запуском задайте платформу:

```bash
export DOCKER_DEFAULT_PLATFORM=linux/amd64
./scripts/mongo-init.sh
```

Эмуляция может увеличить время запуска приложения.

## Признаки успешного запуска

Этап выполнен успешно, если:

- все пять контейнеров находятся в состоянии `Up`;
- скрипт завершается сообщением `Инициализация завершена.`;
- в кластере зарегистрированы два шарда;
- коллекция `somedb.helloDoc` содержит 1000 документов;
- `getShardDistribution()` показывает данные на обоих шардах;
- `curl http://localhost:8080` возвращает `status: OK` и топологию `Sharded`;
- Swagger UI открывается по адресу `http://localhost:8080/docs`.
